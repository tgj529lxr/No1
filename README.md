# 考勤助手（离线 OCR 考勤表自动填写）

> 贵州民族大学 · 辅导员 / 任课教师专用小工具
> **完全离线运行**：拍照识别请假条 → 自动按课表展开考勤明细 → 生成考勤表 → 打印或导出 Excel。

---

## 一、这个应用能做什么

| 功能 | 说明 |
| --- | --- |
| 📷 离线拍照识别 | 在手机相册选图或直接拍照，本地 OCR 引擎（Tesseract chi_sim，跑在本机浏览器里）识别请假条，**图片不上传任何服务器** |
| 🧠 结构化解析 | 从 OCR 文本里抽出「姓名 / 学号 / 请假起止日期 / 节次 / 请假事由」 |
| 📅 自动按课表展开 | 结合内置课程时间表，把「9 月 1 日到 9 月 3 日」自动拆成每天每一大节的缺勤明细，并按学生汇总到一张考勤表 |
| 🖨️ 打印 / 导出 | 一键调用浏览器打印(A4 横向)，或导出 `.xlsx` 交到教务 |
| ✍️ 识别不准可手改 | 识别结果每一条都能手动修正；也支持直接粘贴请假条文字、或纯手动填写 |
| 🔒 数据只在本机 | 课表、学生名单、历史请假记录全部存在**本设备的浏览器 / App 本地存储**里 |

## 二、怎么用（三种方式，任选一种）

### 方式一：当成 Web App（安卓 + iPhone 都能用，免费，推荐）

只要仓库的 GitHub Pages 部署过一次（见下方「首次准备」），就会得到一个网址：

```
https://<你的 GitHub 用户名>.github.io/<仓库名>/
```

**Android（Chrome / Edge）**

1. 用 Chrome 打开上面的网址
2. 右上角 **⋮** → **添加到主屏幕（Add to Home screen）** / **安装应用**
3. 桌面出现图标，以后点图标就像打开 App，地址栏不出现

**iPhone / iPad（Safari，注意必须用 Safari，Chrome 不行）**

1. 用 **Safari** 打开上面的网址
2. 底部 **分享按钮**（方框向上箭头）→ 往下滑找到 **添加到主屏幕**
3. 命名后点「添加」，桌面出现图标

> ✅ **之后断网也能用**：第一次打开时浏览器会把 OCR 引擎和数据缓存到本地，之后坐地铁、在教室里没信号也能正常识别。

> ### ⚠️ **「添加到主屏幕」这一步请不要跳过**（iPhone 用户尤其重要）
>
> 这一步不只是加个图标，它会把站点标记为"已安装的应用"，直接影响**缓存能保留多久**：
>
> - **iOS Safari 的规律**：对**没有**添加到主屏幕的站点，如果你**大约 7 天没有访问过**，Safari 会自动清掉它的存储空间（包括 14MB 的 OCR 引擎和语言包）。清除之后离线识别会失效——打开 App 会停在"引擎加载失败"，或者提示离线包不完整。
> - **怎么办**：**重新联网打开一次**即可恢复（会自动重新把引擎下载回本地，约 14MB）。
> - **添加到主屏幕之后**，Safari 会把主屏幕图标的站点视为已安装应用，存储被清理的概率大幅降低，日常使用基本不会再遇到这个问题。
> - 无论哪种情况，**你录入的课表和考勤数据不会丢**（它们在 localStorage 里，与 OCR 引擎分开管理），只有 OCR 引擎需要重下一次。
>
> **Android 上问题要轻得多**：Chrome 对已安装 / 高频访问的站点基本不会主动清理，配合 Route 3 的 APK 就是彻底免疫。
>
> 📌 **APK 不受此限制**：方式二打包出来的安卓 APK，所有资源（引擎、语言包、图标）是**打包进安装文件里的**，随 App 一起安装、不会被浏览器回收，装完即使一直不联网也不会失效。下面会讲怎么下载 APK。

### 方式二：安卓 APK 安装包

适合 Android 手机，装完是一个真正的独立 App（桌面图标、独立窗口、不显示网址）。

> 📌 **APK 不受上文「7 天清理缓存」的限制**：引擎、语言包、图标全部**打包进 App 安装文件**，不存在浏览器回收的问题，也不会因为长时间不联网而失效。iPhone 用户请回到方式一并选择「添加到主屏幕」。

1. 打开仓库页面 → 顶部 **Actions** 标签
2. 左侧点 **构建安卓 APK**
3. 右上角 **Run workflow**（绿色按钮）→ 再点一次 **Run workflow** 开始云编译
4. 等 5～10 分钟，圆圈变 ✅ 后，点进这次运行记录
5. 页面最下方 **Artifacts** 区域，点 `attendance-helper-debug-apk` 下载得到一个 `.zip`
6. 解压出 `attendance-helper-debug.apk`，传到手机安装

**安装时需要注意**：

- Android 会提示「未知来源应用」/「此应用可能存在风险」→ 选 **允许本次安装**（或到 设置 → 安全 → 允许安装未知应用，给文件管理器/浏览器授权）
- 若提示「Play 保护机制」→ 点 **仍然安装**
- 首次打开若询问相机权限，允许即可（拍照识别要用）

> ℹ️ 每次往 `main` 分支 push 代码，也会自动触发一次 APK 编译。

## 五、常见问题

**Q1：为什么 iOS 不能直接上架 App Store？**
因为 App Store 上架需要 Apple 开发者账号（**¥688 / 年**），且必须在 macOS + Xcode 上打包。目前先用「添加到主屏幕」的方式，体验和原生 App 几乎一样（全屏、有图标、离线可用）。后续如果有开发者账号，本项目已经是标准 Capacitor 工程（见 `capacitor.config.json`），直接加 iOS 平台就能上架，网页代码一行都不用改。

**Q2：第一次打开很慢 / 流量消耗大？**
OCR 的中文识别引擎 + 字典约 **14MB**，第一次打开时会下载并缓存到本机（图标期末或清理浏览器数据会清掉，届时再下一次）。之后访问秒开。**建议在 WiFi 下首次打开**。

**Q3：识别不准怎么办？**
按顺序试：

1. **拍清楚**：光线充足、正对请假条、铺平不要有阴影；别用超广角（边缘会变形）
2. **改识别模式**：应用内【设置】→ OCR 参数 → 把 PSM 切成 **11（稀疏文本）**，请假条字少且分散时效果好很多
3. **关掉图像预处理**：某些截图/白底图片，预处理反而会损伤笔画
4. **直接粘贴文字**：如果请假条是微信群里的**文字消息**，复制后粘贴到输入框，比 OCR 准 100%
5. **手动填写**：识别错了不要紧，结果表格里的每一格都能直接点开改

**Q4：换了手机 / 换了电脑，之前录入的课表、学生名单还在吗？**
**不在。** 所有数据都存在"当时那台设备"的浏览器/App 本地存储里，**不同设备之间不会自动同步**——这是为了做到完全离线、不碰任何服务器。换新设备后可以：

- 老设备上用【导出】把考勤表导出成 Excel，传到新设备导入/打印；
- 或在新设备上重新录入一次课表与学生名单（录一次长期有效）。

**Q5：卸载 App / 清理浏览器会丢数据吗？**
会。清理浏览器数据、卸载 APK、清理手机缓存都会清掉本地存储。重要的表记得先导出 Excel 保存。

**Q6：编译 APK 失败了怎么办？**
进 Actions 页面点开失败的运行，看红色那一步的日志。常见原因：仓库里缺 `dist/`（见上方 Q3 提示）、或 GitHub Actions 未开启（Settings → Actions → Allow all actions）。

## 六、项目结构（给想改代码的人）

```
考勤app/
├── src/index.html          # 应用全部源码（单文件，HTML+CSS+JS）
├── build-tools/
│   ├── build.js            # src → dist 构建
│   └── gen-icons.js        # 生成 PWA 图标
├── dist/                   # 构建产物，也是 GitHub Pages 的发布目录
│   ├── index.html
│   ├── manifest.webmanifest
│   ├── sw.js               # Service Worker，负责离线缓存
│   ├── vendor/             # 离线 OCR 引擎 + 字典 + Excel 库
│   └── icons/
├── capacitor.config.json   # Capacitor 配置（打 APK 用）
├── .github/workflows/
│   ├── build-apk.yml       # 云编译安卓 APK
│   └── deploy-pages.yml    # 部署到 GitHub Pages
├── tests/                  # 自测脚本：run-tests.js / test-offline.js / test-sw-ui.js /
│                           #           test-sw-fallback.js / check-workflows.js / check-assets.js
└── package.json
```

本地开发常用命令：

```bash
npm run build      # 重新生成 dist（改完 index.html 必跑）
npm run icons      # 重新生成 PWA 图标
npm run check      # 一键自检：功能测试 + CI 工作流校验 + dist 资产/体积断言
npm test           # 只跑功能测试（186 项）
npm run test:offline   # 离线 / PWA / CI 回归（135 项）
npm run test:swui      # Service Worker 告警 UI 行为（30 项）
npm run test:swfb      # Service Worker 旧缓存兜底行为（37 项）
node tests/check-workflows.js   # 只校验 CI 工作流配置（零依赖）
node tests/check-assets.js      # 只断言 dist 资产齐全度与体积
npm run sync       # 在本机生成/同步 android 工程（需要已装 Android SDK）
```

Service Worker 的缓存策略（改 `dist/sw.js` 前请先读）：

- 关键资源（OCR 引擎 wasm / 语言包 / 首页 / Excel）只要有一条没缓存成功，install 就**抛错作废**，新 SW 被丢弃、旧缓存继续服役，页面弹出「离线包下载不完整」告警条并提供「重新下载离线包」。
- 抓取失败时会**先回查本地旧副本**：旧缓存里已有这份资源就视为成功，不弹告警——避免「缓存明明是好的，弱网打开却被误报」。
- `CACHE_VERSION` 刻意保持 `v1`：新旧 SW 同名缓存，老用户已有的完整缓存直接复用，发版不会清空重装 14MB。**除非要强制全网刷新缓存，否则不要递增它。**

## 七、隐私说明

- **所有识别都在本机完成**，不联网、不上传任何图片或学生数据
- 应用不含任何第三方统计、埋点、广告 SDK
- 数据存在 `localStorage` / IndexedDB，只属于当前设备
